# 示例笔记：如何组织个人知识库

> 这是一篇**示例笔记**，用来演示常用写法。写完自己的第一篇笔记后，可以直接删掉本文件。

## 为什么要有一个统一入口

笔记散落在各个 App 里的最大问题是**找不回来**。一个很朴素但有效的做法：

1. 所有笔记都是纯 Markdown，放在一个 Git 仓库里；
2. 目录结构只分两层（领域 → 主题），不要超过三层；
3. 每篇笔记开头写清楚「结论先行」，细节放后面。

## 目录结构示例

```text
notes/
├── backend/
│   ├── mysql-index.md
│   └── redis-expire.md
├── frontend/
│   └── vite-config.md
└── 2026/
    └── 0115-weekly.md
```

## 笔记模板

下面的模板可以直接复制到新文件开头：

```md
---
title: 标题（一句话说清这篇讲什么）
date: 2026-01-01
tags: [mysql, 索引]
---

## 结论

一句话结论。

## 背景

为什么要解决这个问题。

## 方案

1. ...
2. ...

## 参考

- 链接
```

## 一些记录习惯

| 习惯 | 好处 |
| --- | --- |
| 结论写在最前面 | 三个月后回看不用重新读一遍 |
| 代码贴可运行的最小片段 | 复制即用 |
| 记录当时的报错原文 | 以后搜关键词能命中 |
| 每个概念留一个自己的例子 | 别人的定义记不住，自己的例子记得住 |
